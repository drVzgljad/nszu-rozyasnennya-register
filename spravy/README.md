# Справи відділу (`spravy/`)

Дошка доручень відділу: одна картка = одна справа, від вхідного з АСКОД до вих. №.

| Етап (`stage`) | Колонка | Що означає |
|---|---|---|
| `new` | Нове | зареєстровано в АСКОД, до роботи ще не взялися |
| `work` | Готуємо | є виконавець і чернетка v1…vN |
| `review` | Погодження | рецензія, керівник; зауваження — окремими пунктами |
| `signing` | На підписі | файл у `10_НА_ПІДПИС\ДД.ММ.РР` |
| `sz_sent` | СЗ надано | ми співвиконавці: СЗ у робочому порядку передано головному виконавцю |
| `done` | Закрито | вих. № є, резолюцію закрито (або «не наше» / «до відома») |

Угорі картки — **головний виконавець** (`lead_unit`: департамент / управління / відділ) і **наша роль**
(`our_role`: `lead` головні, `co` співвиконавці, `info` до відома).

Кнопки картки пишуть в **історію справи** з датами:
- **⏱ Продовжити строк**: новий строк і підстава. Первинний строк лишається в `deadline_original`, на дошці
  такий строк позначено ↻.
- **↩ Повернуто на доопрацювання**: хто повернув і що сказав. Картка йде в «Готуємо», а сказане
  потрапляє в «Зауваження» як невраховане.
- **📤 Відправлено документ**: лист, СЗ чи СЗ у робочому порядку, з №, датою й адресатом. Тут же можна
  перевести справу в «СЗ надано» чи «Закрито».
- **🔔 Нагадування**: дата й текст. Коли день настає, нагадування з'являється в смузі над дошкою.

## Як потрапити й чим користуватися

- **Вхід:** кнопка «📋 Справи» вгорі (усі співробітники), вкладка «Справи» в нижній панелі на телефоні,
  плитки «Мій робочий стан» на головній, смуга «Мої справи в роботі» вгорі сторінок. Посилання
  приймають `?mine=1`, `?f=hot|overdue|remind`, `?case=<id>`, `?new=1` (форма нової справи —
  кнопка «＋ Доручити справу» для керівництва).
- **Доручити** = завести справу з виконавцем: виконавець отримає сповіщення «Вам призначено справу».
  Старі «Доручення» СКО-Д (`skod/tasks.html`) — архів; «Простір відділу» в кабінеті прибрано.
- **Вигляди:** «Дошка» (етапи), «Список» (за строком, прострочене зверху), «За виконавцями»
  (хто що тримає, «горить / прострочено»). Виконавцям за замовчуванням — «лише мої».
- **На картці дошки** кнопка «далі →» — наступний етап одним кліком; справу без виконавця бере на себе.
- **🕒 Зарахувати в СКО-Д:** запис обліку роботи заповнюється зі справи (вх. №, суть, відправлений
  документ); після «📤 Відправлено документ» форма відкривається сама.

## Дані

Supabase, міграції `../migration_2026-11-02_dept_cases.sql` і `../migration_2026-11-02b_dept_cases_history.sql`
(застосовує власник, по черзі):

- `dept_cases` — картка: реквізити вхідного, строк, резолюція, тип відповіді, етап, виконавець,
  версія, шлях до файлу в обміннику, посилання (Google Doc), нюанси, рецензія, вих. №.
  Унікальність — `(department, in_no)`.
- `dept_case_events` — стрічка: `comment`, `remark` (зауваження: `remark_from`, `remark_status`
  open/done/rejected, `remark_answer` — як враховано, `remark_version`) і автоматичні записи
  `stage` / `version` / `executor` / `review` / `system`, які пише **тригер бази**. Тому стрічка
  повна, хоч би хто змінив картку: сторінка, скрипт чи Claude напряму через SQL.
- Історія (міграція b): тригер сам пише `deadline` (зміна строку) і `returned` (етап назад). Підставу
  зміни передають у `dept_cases.change_note` тим самим `update`: тригер дописує її в подію й
  очищає поле. Вручну додаються `outgoing` (`doc_kind`, `doc_no`, `addressee`, `event_date`) і
  `reminder` (`due_date`, `done`). `event_date` — дата документа, якщо його вносять пізніше.
- RLS: читає свій відділ (`profiles."Section"`), керівництво департаменту і діловод (`is_clerk`);
  пише свій відділ і керівництво; видаляє керівник відділу або керівництво. Гостям — нічого.

У репозиторії даних немає й не буде: він публічний. Демо-режим `?demo=1` показує вигадані картки
й нічого не пише в базу. Ним зручно дивитися вигляд до застосування міграції.

## Наповнення з АСКОД

`D:\pmg-data\tools\spravy_sync.py` (поза репозиторієм порталу):

- бере найсвіжіший `journal_*.xlsx` **кожного виконавця** у `00_ВХІДНЕ` (власник файла — найчастіше
  значення колонки «Виконавець»; журнали зводяться разом) і заводить свіжі справи (за 45 днів або з живим
  строком, без «до відома»), виконавця зводить із профілем за прізвищем та ім'ям. «Зниклими з журналу»
  вважаються лише справи власників журналів: 03.11.2026 журнал колеги позначив зниклими 66 чужих справ;
  документ, що повернувся в журнал, позначку втрачає;
- з `10_НА_ПІДПИС\_Контроль_листів_на_підпис.xlsx` бере актуальну версію листа → версія, шлях,
  етап «На підписі»; ручний «Стан» «зареєстровано / відправлено» + вих. № → «Закрито»;
- етап лише просуває вперед, ручних полів не чіпає; справу, що зникла з журналу, не закриває,
  а позначає в «Стан АСКОД».

Щоденно — само: один раз `python tools/spravy_sync.py --login` (пароль вводить власник; зберігається
refresh-токен, зашифрований DPAPI Windows, у `~/.pmg/`), далі завдання планувальника `PMG_Spravy_Sync`
(будні, 09:30) запускає `pythonw tools/spravy_sync.py --auto`. Підсумок — у `~/.pmg/spravy_sync.log`;
«потрібен --login» там означає, що вхід треба повторити. Не `%LOCALAPPDATA%`: термінал Claude Desktop
працює в пакеті, і Windows перенаправила б туди AppData — планувальник токена не побачив би.

```
python tools/spravy_sync.py            # холостий прогін
python tools/spravy_sync.py --sql      # SQL у %TEMP%\spravy_sync.sql — для конектора Supabase / SQL Editor
python tools/spravy_sync.py --push     # записати під своїм логіном порталу (під RLS)
```

## Як Claude веде картки

Claude пише через конектор Supabase (`execute_sql`). Конектор працює в обхід RLS, тому кожна зміна
підписується `updated_by_name = 'Claude'`, а в подіях — `author_name = 'Claude'`. Відділ —
`department = 'наукова та клінічна експертиза'` (або той, у якому справа).

Початок сесії — що горить:

```sql
select in_no, deadline, stage, executor_name, version, review_passed, left(subject, 80) subject,
       (select count(*) from dept_case_events e
         where e.case_id = c.id and e.kind = 'remark' and e.remark_status = 'open') open_remarks
from dept_cases c
where department = 'наукова та клінічна експертиза' and stage <> 'done'
order by deadline nulls last;
```

Робота над листом:

```sql
-- взялися / нова версія чернетки (тригер сам запише «Нове → Готуємо» і «Чернетка v2»)
update dept_cases set stage = 'work', version = 2,
       draft_path = '19_службові_записки\letter_10001_..._v2.json', updated_by_name = 'Claude'
where department = '…' and in_no = '10001-08-26';

-- зауваження керівника з Google Docs — по одному рядку на пункт
insert into dept_case_events (case_id, author_name, kind, body, remark_from, remark_status)
select id, 'Claude', 'remark', 'Другий абзац скоротити', 'Директор департаменту', 'open'
from dept_cases where department = '…' and in_no = '10001-08-26';

-- враховано у v3
update dept_case_events set remark_status = 'done', remark_answer = 'Абзац зведено до однієї тези',
       remark_version = 3 where id = '…';

-- рецензію пройдено, лист у 10_НА_ПІДПИС
update dept_cases set review_passed = true, stage = 'signing', version = 3,
       draft_path = '10_НА_ПІДПИС\02.11.26\lyst_10001_..._v3.docx', updated_by_name = 'Claude'
where department = '…' and in_no = '10001-08-26';

-- коментар у стрічку
insert into dept_case_events (case_id, author_name, kind, body)
select id, 'Claude', 'comment', 'Чекаємо дані ДІТ щодо оплат' from dept_cases where …;

-- головний виконавець і наша роль
update dept_cases set lead_unit = 'Юридичний департамент', our_role = 'co', updated_by_name = 'Claude'
where …;

-- строк продовжено (тригер запише «Строк: 28.10 → 15.11 — продовжено: …», первинний збережеться)
update dept_cases set deadline = '2026-11-15', change_note = 'продовжено: лист кореспондента від … № …',
       updated_by_name = 'Claude' where …;

-- повернули на доопрацювання (тригер запише «Повернуто: Погодження → Готуємо — …»)
update dept_cases set stage = 'work', change_note = 'Директор департаменту: скоротити вступ',
       updated_by_name = 'Claude' where …;

-- відправлено СЗ у робочому порядку → «СЗ надано»
insert into dept_case_events (case_id, author_name, kind, body, doc_kind, doc_no, addressee, event_date)
select id, 'Claude', 'outgoing', 'Позиція відділу', 'sz_work', '3-19/60-26', 'Юридичний департамент', '2026-11-02'
from dept_cases where …;
update dept_cases set stage = 'sz_sent', updated_by_name = 'Claude' where …;

-- нагадування
insert into dept_case_events (case_id, author_name, kind, body, due_date, done)
select id, 'Claude', 'reminder', 'Перевірити, чи головний виконавець відповів', '2026-11-10', false
from dept_cases where …;

-- нагадування на сьогодні (на початку сесії)
select c.in_no, e.due_date, e.body from dept_case_events e join dept_cases c on c.id = e.case_id
where e.kind = 'reminder' and e.done is not true and e.due_date <= current_date order by e.due_date;
```

Ініціативний лист без вхідного — `in_no` порожній, `source = 'claude'`.

## Голосова кімната відділу (voice.js, з 03.11.2026)

Постійна кімната, як у Discord: відкрив «Справи» — і ти в кімнаті свого відділу.
Видно, хто зараз тут, і чути тих, хто говорить. Мікрофон за замовчуванням вимкнений,
а «Вийти» браузер запам'ятовує (`localStorage['spravy-voice-off']`).

- `voice.js` тут — лише **панель**. Сам голос — спільний рушій порталу
  `../zviazok/voice.js` (той самий, що в «Чаті департаменту», зведено 03.11.2026):
  з'єднання, TURN, мікрофон/🎧, перепідключення правлять там. «Вийти» — його режим
  «лише дивлюся» (`exit()` / `enter()`). Версію рушія піднімають в імпорті нагорі
  `voice.js`. Кімната департаменту `voice:all` — та сама, що голос головної стрічки чату.
- `?room=dept|all` — пряме посилання на кімнату відділу чи департаменту.
- Голос іде **напряму між браузерами** (WebRTC, кожен з кожним) і ніде не зберігається.
  Розраховано на 3–10 людей; від 10 панель попереджає.
- Через приватний канал Supabase Realtime `voice:dept:<16 hex SHA-256 від Section>`
  проходять лише присутність і рукостискання з'єднань. Впускають у канал RLS-правила на
  `realtime.messages` з `migration_2026-11-03_voice_room.sql`: свій відділ плюс
  керівництво. **Доки міграцію не застосовано, панель пише «Кімната ще закрита».**
- Якщо мережа не пускає пряме з'єднання, біля імені горить «⚠». Тоді потрібен
  ретранслятор Cloudflare TURN: воркер `tools/voice-turn/` (там же README), адреса —
  `VOICE_TURN_URL` угорі `../zviazok/voice.js`.
- Версію `voice.js` піднімають в імпорті нагорі `spravy.js`, а не в HTML.
- Перевірка без логіна: `?demo=1` показує панель із вигаданими учасниками.

## Форма 37-Д зі «Справ» (tools/spravy_37d.py, з 03.11.2026)

Щотижневі рядки «Процеси / Поточний стан виконання» збираються з моїх справ та їхньої історії:
що за період пішло на підпис, повернуто й доопрацьовано, надано СЗ, відправлено з вих. №,
що в роботі. Листи групуються номерами вхідних, ініціативні справи — окремими рядками.

```
python tools/spravy_37d.py --from 03.11.2026 --to 07.11.2026          # рядки в консоль
python tools/spravy_37d.py --from 03.11.2026 --to 07.11.2026 --docx   # бланк 12_форма 37\dod37.docx
```

Вхід — той самий, що в `spravy_sync.py` (`--login` один раз). Бланк заповнюють функції
останнього `12_форма 37uild_dodatok37d_*.py`. Дату підпису скрипт бере з теки
`10_НА_ПІДПИС\ДД.ММ.РР` у шляху чернетки: перша синхронізація 02.11 записала жовтневі листи
як «На підписі» датою запису. Участь у зустрічах у «Справах» не ведеться — ці рядки окремо.
